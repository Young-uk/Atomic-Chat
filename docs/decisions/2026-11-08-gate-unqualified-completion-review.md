# Keep unqualified completion review disabled in this release

- **Context:** The unchanged production completion-review helper, tested on IQ3 Strata, classified the conditional offer "If you want, I can check it for you." as `needs_tool`. This is a semantic qualification failure, not permission to perform the offered action. The completed repeated suite passed 45/48 cases: all three conditional-offer repeats failed with this false `needs_tool`, with zero unavailable responses and byte-identical foreground state restoration. Evidence: `feature-integration/qualification/private-qa/initial-20261108T002105Z/STAGE-RESULT.json` under the task root. Dstar advertises completion review independently, so trusting backend advertisement would enable an unqualified automated continuation path in the new app.
- **Decision:** The app capability adapter returns `completionReview: false` for both managed engines in this release, regardless of backend advertisement. Do not tune the helper prompt or acceptance cases to conceal the failure. Re-enabling requires a separately reviewed change backed by qualification of the exact model/helper/runtime. The backend API itself is unchanged; external clients are outside this app-only gate.
- **Preserved behavior:** Summary capabilities, token counting, bounded admission, cache measurements, visible tool preambles, ordinary real tool calls and their result continuations remain independently negotiated. No transcript, original message, approval policy or model selection is rewritten. The existing review helper and transport implementation remain available for isolated tests but are not activated by production discovery.
- **Verification:** Focused capability tests cover both true/false backend advertisements, Strata summaries, and Dstar preamble versions 3/4 plus summaries. Existing helper and transport regression tests remain required; full release aggregate verification follows final integration. Disabling a failed feature is not a claim that its classifier error is resolved.
