# Expose owned Strata controls on its endpoint card

## Context

Custom Endpoint showed Dstar lifecycle controls but no equivalent for the
registered Strata service. A user could select Dstar while an owned Strata
process remained alive, leaving no visible way to stop that process. Dstar's
Start action was also disabled solely by the selected chat engine.

## Decision

- Render Strata controls only for the exact registered loopback endpoint,
  provider identity, and served model. Viewing the card polls status only.
- Lifecycle clicks use the existing native owner and its authenticated drain,
  request-idle, process-identity, and stop-before-start protections.
- Stop remains available for an owned loading or failed Strata service even
  if another chat model is selected. Never offer Stop for external listeners.
- Share coordinator cancellation when stopping its current target, so an
  in-progress renderer start cannot remain polling a stopped process.
- Refuse lifecycle changes during foreground replies and approval waits;
  serialize repeated clicks and prevent overlapping start transitions.
- An explicit Start may select the engine's verified served model once ready.
  It does not replace a newer selection the user makes while loading.
- Reconcile an explicit panel start's verified owned-ready snapshot into the
  same coordinator target without starting it again. Reject stale targets,
  in-flight transitions, busy work, unowned or erroneous snapshots, and wrong
  served models. This clears a previous error without replacing native model
  or context configuration.
- Dstar Start is no longer blocked merely because Strata is selected. The
  native Dstar action must use coordinated switching, not direct co-loading.
- Keep full model/provider identity checks in the chat dropdown lifecycle UI.

## Verification

Focused component/endpoint tests cover read-only mounting, explicit start,
owned failed-server stop, external listeners, busy/repeated clicks, selection
changes, and unmount. Chromium layout tests cover 1024/1280 windows, Medium
and Extra Large fonts, English/Korean, both themes, and lifecycle states.
No inference or user conversations are generated by these tests.
