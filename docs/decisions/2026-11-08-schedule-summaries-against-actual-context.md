# Schedule both local engines against actual foreground context

- **Context:** The user requested the same automatic-summary scheduling policy for Strata and Dstar, while retaining 64K context, Max, original conversations and foreground priority. Strata previously lowered its scheduling denominator to the qualified native main-token limit.
- **Decision:** Both engines now use actual advertised foreground context: schedule after a completed turn when unarchived raw dialogue exceeds 60%, or the estimated full request envelope reaches 85%. The latter includes system instructions, tools and output reserve. At 65536 tokens, the thresholds are 39321.6 and 55705.6 respectively. Native admission is a separate decision, not a scheduling denominator.
- **Preserved safeguards:** Strata's current 8192 main-token admission limit, snapshot/cache byte bounds, runtime pins, memory checks, refusal latch and capability checks remain unchanged. Original messages remain available; only completed matching archives may replace historical content in model-bound requests. Completion review remains disabled. No backend/native changes or larger qualification claims accompany this policy change.
- **Limitation:** Matching trigger percentages is not functional parity at default 64K. An ordinary 60% trigger already exceeds the 8192 main-token admission bound, even before fixed instructions and tools. Such requests must defer safely; this change does not make high-context Strata automatic summary operational. Supporting those states requires separate qualification and explicit bound changes. The user declined further real-model/load tests for this update; no untested high-context safety claim is made.
- **Verification:** Focused policy and transport-harness expectations were updated to actual-context scheduling while retaining independent admission and preservation assertions. No tests or builds were run during this edit. Required release verification/build is owned by the operator after normal idle shutdown.
