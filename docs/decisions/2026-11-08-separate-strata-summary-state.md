# Separate experimental Strata summary state from foreground state

- **Context:** The user requested Dstar-like automatic summaries with shared weights and a dedicated 16K state, preserving actual 64K context, original messages, main-request priority, cancellation, images, context/cache reporting and engine selection. The user will run real-model tests; this release must not claim empirical qualification for untested state sizes.
- **Decision:** Strata protocol 4 uses a separate mutable-state bank while weights and compute remain shared. GPU execution is serialized. The backend explicitly negotiates the new protocol and exact runtime identity, rather than widening the old protocol-3 disk snapshot envelope. The application accepts the new contract only when the server advertises the exact isolation, 16K capacity, positive state budget, shared weights, serialized compute, experimental provenance and warmup limitation. The old 8K snapshot admission bound does not apply to this distinct implementation.
- **Scheduling and preservation:** Both engines retain the actual-context 60% raw-history and 85% full-envelope triggers. A completed summary may update only its matching archive scope; original messages remain stored. Strata foreground arrivals cancel background summaries and wait until the main bank is restored. Uncertain switches poison the lane and block further inference pending a restart. Memory or unsupported-mode refusals retain the main conversation and defer summary without a busy retry loop. Native memory admission remains authoritative.
- **Limitations:** The separate bank has a 1 GiB allocation budget, dynamic memory checks and a required foreground prompt-scratch warmup. It cannot summarize immediately after a pristine process start. This is not cold-start parity with Dstar. Main and summary compute are not concurrent. Summary input is text-only; the foreground bank retains image and cache state. Experimental provenance is visible. Completion review stays disabled independently of the summary lane.
- **Deployment:** Use separately versioned native and Python runtime paths, retaining the existing app and backend baseline for rollback. Preserve all model files, SD backups, conversations, settings and the chosen engine. Recompute strict native/backend/model-config pins for the staged artifacts and actual launch environment; do not reuse old empirical qualification claims.
- **Verification:** Required static, CPU/fake protocol and build checks are performed before installation. Requested app startup and read-only capability checks are permitted. No real-model generation or load testing is performed for this release, at the user's request; long-context, image continuity, repeated cancellation and memory behavior remain for user validation.

- **Startup integration correction:** The first staged state-bank build conservatively excluded the actual IQ3 expert-streaming path and therefore advertised no usable summary slot at startup. Do not remove that guard without ownership work and do not replace streaming with resident weights. The follow-up implementation preserves the shared expert-weight arena, drains its pending I/O, explicitly fences and releases prompt-region ownership, clears stale dispatch aliases and requires the existing streaming prompt scratch to be warm. The 16K sequence state remains separate; expert-weight cache statistics may change. Startup capability checks are required before claiming summary enablement, and still do not establish runtime output/state safety.
