# Keep desktop overlay interactions on the current app

The overlay previously disabled keyboard focus, but a mouse click could still activate Atomic Chat. Configure activation prevention on the existing Tauri-owned NSWindow on the main thread using the capability-checked AppKit selector. Preserve Tao class and instance variables; never replace the native class. Show with orderFrontRegardless to avoid the framework's activating show path. Keep existing opaque one-shot approval identities, stale-decision rejection and approval semantics.

The title invokes a dedicated label-checked drag command because the general window-drag capability is intentionally not granted to this auxiliary window. No extra general window permissions or dependencies are added. Clip the native content layer and transparent HTML background to the same 18-point radius. Clamp requested physical dimensions to the monitor work area after size changes; do not read stale outer dimensions after asynchronous macOS sizing. Preserve the dragged position whenever it fits.

The AppKit selector is private and checked at runtime. A metadata-only native test verifies its availability on this Mac; unsupported systems log a warning. User interaction must also verify that dragging and one-shot decisions preserve the foreground app.

The main approval dialog also suppresses opening autofocus, the explicit approval-button autofocus and closing focus restoration while its document is not focused. This avoids a DOM focus handoff undoing native overlay activation prevention after a decision. A DOM regression test checks that an approval opened in the background leaves the previous element focused.
