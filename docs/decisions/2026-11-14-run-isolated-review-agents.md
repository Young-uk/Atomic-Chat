# 2026-11-14 — Run source-grounded review agents in an isolated cache bank

- **Context:** The extractor could not inspect and improve existing skills. Its completion callback had no persisted-message fallback and ignored MCP error results. Continued messages could repeat evidence IDs; array-wrapped failed tools were not checked recursively. The installed runtime also lacked the repository's auxiliary JSON-format support.
- **Decision:** Add a restricted host-executed review agent. The model emits one JSON tool decision at a time; the host permits only durable-note search/read/add and skill list/read/create/patch, followed by finish. No general native tools, shell, browser, external messaging or executable skill files are exposed. Source quotes are mandatory for writes. Existing skills require a read of the current revision before an exact patch. Notes are agent-authored additions, never destructive rewrites of human memory.
- **Trigger and priority:** Persist observation deduplication and per-conversation cadence (ten user turns, fifteen tool iterations). A provider verifies persisted completed messages to supplement missed transport callbacks. Prefer user evidence before tool-heavy text consumes the window; exclude private reasoning, binary blocks and failed results. Coalesce waiting work for the same conversation. Wait for fifteen seconds of foreground/summary idleness, cancel for foreground work and bound automatic requeues. Disabling the feature cancels waiting agent work.
- **Cache:** A capability-gated Strata auxiliary chain holds one existing isolated state-bank transaction across all host tool callbacks. It forks the completed main cache once, then reuses the growing review prefix with AGEN. END restores the latest main state on completion, cancellation or error. Callbacks use a per-run authenticated fixed IPv4 loopback route; redirects and arbitrary callback URLs are not accepted. No native weights or default generation paths change. Servers without the resident-chain capability use an explicitly per-request fallback, not a claimed retained-KV path.
- **Persistence and UI:** Note writes and their audit records share one database transaction. Skill changes use a prepared journal, atomic file replacement and recovery checks; external edits prevent silent overwrite or undo. Existing learned-change history presents actual writes and supports undo. Completed changes invalidate cached skill bodies and produce a user notification. Observation counts, failures, active tools and cache mode are available to status polling. No-change reviews do not pretend to have learned something.
- **Validation:** Source tests cover actual host callbacks, cadence/restart deduplication, failed/binary/duplicate evidence, read-before-edit, path boundaries, versioned memory, multi-edit undo, foreground cancellation and restoration of the main bank. Deployment requires the full app gates, installed-Node checks, exact runtime pins, original-cache compatibility and an isolated live-model tool/cache trial.

- **Launch qualification:** Calculate pins with the same `STRATA_NO_PRESET=1` override as the app. A copied JSON config without that process environment is not sufficient evidence. Run the real Rust 64K/128K read-only configuration test outside Cargo-injected dynamic-library paths before deployment; preserve the exact preceding disk-session identity bridge.
