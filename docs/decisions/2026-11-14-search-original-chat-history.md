# 2026-11-14 — Retrieve original dialogue across related chats

- **Context:** Personal memory recalls selected durable facts, not detailed episodic dialogue. Existing chat search matches titles; compaction archive search is confined to one thread.
- **Decision:** Add the read-only `personal_chat_history` MCP tool with separate search and neighboring-context actions. The app binds the originating thread and local time zone after model argument generation. Search other chats with the same assistant ID and project ID; direct context reads enforce the same scope. The standalone Agent path excludes this tool until it can supply the host binding.
- **Consequences:** The original `messages.jsonl` is authoritative and remains intact through compaction. A worker-local SQLite FTS5 index accelerates keyword/prefix and Korean bigram lookup; it is in memory only, not another persistent transcript. Each search refreshes changed files and purges missing sources before retrieval. Context reads consult live files; archived, edited-away or deleted text cannot reappear. Symlink paths and forged IDs are refused. Only visible user/assistant text is indexed, not reasoning, instructions, memory metadata, images or tool results. Relative dates use the originating user turn and host time zone, including midnight crossings. Date-only fallback is explicitly labeled and never presented as a semantic match.
- **Explicit recall:** Conservative past-dialogue intent triggers a host-initiated, approved and cancellable read before generation. Combined lookup reads the best hit’s neighbors and binds the source fingerprint. Its bounded evidence is saved on that user turn with a text hash and replayed unchanged in the model view; edited user text invalidates it. The UI message remains unchanged. The model is not credited with a fabricated tool call. Optional further reads use the ordinary tool path. This avoids promise-only answers observed in the actual local-model trial.
- **Paging:** Search returns five excerpts by default, with offset paging. Context defaults to three public messages before and after; neighboring anchors and text offsets allow further reads. Per-message truncation is explicit, and total context text is bounded per page. These are retrieval pages, not generation limits.
- **Cache and UI:** New tool descriptions change the catalog once. Optional tool results append through ordinary tool history; host retrieval uses the immutable per-turn model view; the common request policy adds routing guidance once, while stored messages, compaction and native cache protocols are untouched. Source links navigate inside Chat and reveal the original message through the existing Find machinery. No inference-server changes, new dependencies or automatic memory writes are introduced. Existing per-tool approval and cancellation behavior is retained.
- **Validation:** Synthetic source tests cover following corrections, assistant/project boundaries, edits/deletions, paging, private-part exclusion, local dates and midnight crossings, and symlink/path attacks. A real MCP worker test checks discovery and host-only fields. Frontend tests cover origin binding, approval routing, Markdown clicks, custom citation anchors, delayed message loading and external-link rejection.
